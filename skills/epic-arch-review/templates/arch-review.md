## Чеклист: Clean Architecture
- [ ] Слои разделены: UI → use-case → domain → infra (БД, внешние API)
- [ ] Зависимости направлены внутрь (UI знает про use-case, domain не знает про UI)
- [ ] Бизнес-логика не утекает в роуты/компоненты
- [ ] Вызовы ORM изолированы в репозиториях, не в компонентах
- [ ] Нет циклических зависимостей между модулями

Для каждого ❌ — что нарушается и как чинить **в рамках эпика**.

## Чеклист: Применённые паттерны

| Паттерн | Боль из эпика | Обоснован? | Риск over-engineering | Вердикт |
|---|---|---|---|---|
| Repository | ... | да/нет | низкий/средний/высокий | оставить / упростить / убрать |

**Красные флаги:**
- Паттерн «на будущее» без конкретной боли → убрать.
- 3+ уровня абстракции на простой CRUD → упростить.

# goon — возврат фонового рана в чат

Движок общий со скиллом `/go`: `../go/go.sh` (раны в `~/.claude/go-runs/<name>/`,
tmux-сессии `go-<name>`). Терминальные состояния рана — файл `state`:
`finished <код>` / `failed <причина>` / `stopped`; `running` при мёртвом tmux означает
«упал, ждёт watchdog» (авто-восстановление, до 3 рестартов).

## Как выполнять

### 1. Найди ран

```bash
"<папка скиллов>/go/go.sh" list
```

- имя передано (`/goon <имя>`) — бери его;
- ранов нет — так и скажи: «фоновых ранов нет, уводить в фон — /go»;
- ран один — бери его без вопросов;
- ранов несколько и имя не передано — покажи список одной таблицей и спроси, какой вернуть
  (самый свежий предложи первым; статус «завершена·не доложена» — главный кандидат).

### 2. Если ран ещё работает (`list` показывает «жива»)

Не жди и не блокируй чат:

- `go.sh log <имя> 10` — покажи 3-5 последних строк: что он сейчас делает;
- если у пользователя есть дополнение к задаче — `go.sh say <имя> "<текст>"`:
  живой ран подхватит его после текущего прохода;
- если в этом чате нет активной вахты завершения (чат переоткрывали) — поставь её:
  Bash `run_in_background: true` → `go.sh await <имя>`, итог придёт сам;
- прервать ран — только `go.sh stop <имя>` (не `tmux kill-session`: убитое руками
  watchdog воскресит как «упавшее»).

### 3. Если ран завершён — верни результат

1. Прочитай `~/.claude/go-runs/<имя>/REPORT.md` (может отсутствовать, если ран упал)
   и `go.sh log <имя> 40`.
2. Код завершения смотри в файле `state` («finished <код>») — это единственный источник
   правды; `failed` / код != 0 — подавай как упавший, с последними строками лога, а не
   как успех; `restarts` в `go.sh status` — скажи, что ран падал и был восстановлен watchdog.
3. Доложи коротко: что сделано, какие решения принял фон, что не сделано и почему,
   что стоит проверить. Ключевые утверждения отчёта дёшево проверяются — проверь
   (файл существует, сервис active, страница отдаёт 200), не пересказывай слепо.
4. Отметь доклад: `go.sh ack <имя>` — иначе хук-напоминалка будет поднимать этот ран
   в каждом сообщении.
5. Продолжай работу в этом чате с учётом результата — правки, следующие шаги, вопросы
   пользователя по сделанному.

### 4. Если пользователю нужен сам диалог фоновой сессии (не только результат)

Полный контекст рана в текущий чат не переносится — это отдельная сессия. Предложи:

- **VS Code:** `/resume` → выбрать «go: `<имя>`» — сессия откроется как обычный чат
  с полной историей (чат должен быть открыт в той же директории, что `--dir` рана);
- **терминал:** `claude --resume <id>` в директории рана (id даёт `go.sh back <имя>`);
- либо догрузить задачу без возврата: `go.sh say <имя> "<что ещё сделать>"`
  (живому — в очередь, завершённому — новый заход).

## Ограничения

- Ран, открытый через `/resume`, и `go.sh more`/`say` пишут в одну и ту же сессию —
  одновременно не совмещать (ран должен быть завершён, продолжение — не запущено).
- Раны старше суток пропадают с доски terra, но папка и REPORT.md остаются
  в `~/.claude/go-runs/` (при переиспользовании имени — в `.old/`).

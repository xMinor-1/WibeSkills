# Video Distill

Превращаешь сырой транскрипт (один файл) в **один** структурированный конспект. Цель — чтобы конспект потом можно было подсасывать в любой другой скилл через `Read` или `@<learning-dir>/<slug>.md`.

**Никаких внешних зависимостей.** Скилл работает в любом репозитории и не требует проектного конфига. Если в репо есть `CLAUDE.md` — можешь прочитать его один раз, чтобы не дублировать уже зафиксированные правила. В остальном действуй по дефолтам:
- Папка вывода: `docs/learning/` (создай, если её нет). Если такого пути не подходит структуре репо — спроси пользователя один раз.
- Язык: тот же, на котором пользователь пишет в чате.
- Approve: не нужен.

## Старт

Approve **не нужен** — это анализ файла, не деструктивное действие.

Если пользователь не указал путь к транскрипту — спроси одним сообщением. Если транскрипт уже виден в контексте чата как paste — работай по нему и сразу запиши исходник в `<learning-dir>/_raw/<slug>.txt`, чтобы поле `source:` в конспекте указывало на реальный файл.

## Шаг 1: Прочитай и классифицируй

Прочитай файл целиком (`Read` без `limit`). Если транскрипт длиннее 1500 строк — читай чанками по 1500.

Определи **kind** по содержимому:

- **`ai-tutorial`** — про AI-агентов, prompt engineering, LLM API, CLI-инструменты, dev-практики, MCP, скилл-инженерию.
- **`product-insight`** — PM-практики, growth, customer development, продуктовые фреймворки (JTBD/AJTBD, RICE, North Star, retention), переговоры с пользователями.
- **`course`** — структурированный курс/серия уроков, где важен список модулей + порядок прохождения. На вход обычно — оглавление, а не один транскрипт.
- **`general`** — если ни одно из выше. Кладёшь конспект, но `applies_to` оставляешь `[]`.

Если контент гибридный — выбирай **доминирующий** kind. Второстепенные темы отражаются в `tags:`.

## Шаг 2: Извлеки ключевые мысли

Для `ai-tutorial` и `product-insight` — основная работа здесь. Цель: **5–12 ключевых мыслей** (не больше — это конспект, не пересказ).

Каждая мысль = блок:
- **Цитата / суть** — одна-две строки из транскрипта, можно слегка причесать пунктуацию.
- **Почему важно** — 1 строка: что нового / контринтуитивного.
- **Как применить** — 1–3 строки. Конкретная привязка: какой паттерн/процесс/инструмент применим. Если в текущем репо есть свод правил (например `CLAUDE.md`) и мысль уже там — пометь «подтверждает правило X», не повторяй текст правила.

Если для мысли нет осмысленной «как применить» — **выбрось мысль**. Конспект должен быть actionable, не энциклопедия.

Для `course` — структура из транскрипта/оглавления: список модулей, чек-боксы, приоритеты, ссылки на уроки. Один большой блок «Ключевые мысли» не нужен — он размывается на модули; мысли извлекаются позже, по мере прохождения.

## Шаг 3: Запиши файл

Путь: `<learning-dir>/<slug>.md`, где `<learning-dir>` = `docs/learning/` по умолчанию (создай папку, если её нет). Если пользователь явно указал другой путь в чате — используй его.

`<slug>` — kebab-case, краткий, описывает **суть**, не источник:
- ✅ `claude-skills-best-practices.md`, `ajtbd-interview-template.md`, `cold-start-marketplaces.md`
- ❌ `youtube-2026-04-some-talk.md`, `transcript-video-3.md`

Если файл с таким `<slug>` уже есть — спроси: обновить / создать `<slug>-v2` / отменить.

Используй шаблон [templates/note.md](templates/note.md). Заполняй **все** поля frontmatter — это контракт для других скиллов:

| Поле          | Что туда |
|---------------|----------|
| `title`       | Короткий заголовок (≤80 симв) |
| `kind`        | `ai-tutorial` / `product-insight` / `course` / `general` |
| `source`      | Путь к исходному транскрипту в репо |
| `source_url`  | URL первоисточника или пусто |
| `applies_to`  | Имена скиллов/процессов, которым этот конспект может пригодиться (kebab-case). Пустой `[]` если не очевидно. Если в репо есть `.claude/skills/` или `_skills/` — посмотри список реальных имён там. |
| `tags`        | 3–6 тэгов lower-case через дефис |
| `date`        | ISO `YYYY-MM-DD` |
| `summary`     | Одна строка ≤120 символов, для индексирования |

## Шаг 4: Отчёт

Кратко, на языке пользователя:

> «Конспект готов: `<learning-dir>/<slug>.md`. Тип: `<kind>`. Применимо к: `<скиллы/процессы>`. Главное: `<1–2 строки сути>`.»

Если в конспекте всплыла гипотеза/идея для бэклога — **скажи отдельной строкой**, не лезь сам создавать задачи. Решение за пользователем.

## Принципы

- **Один транскрипт → один файл.** Не разбивай на части без явного запроса.
- **Actionable > исчерпывающий.** Лучше 6 мыслей с привязкой к практике, чем 20 пересказанных тезисов.
- **Не дублируй правила репо.** Если в репо есть `CLAUDE.md` или подобный свод правил и мысль уже там — пометь «подтверждает X», не переписывай.
- **Frontmatter — контракт.** Другие скиллы могут читать `applies_to`, `tags`, `summary`. Не выдумывай новые поля без необходимости.
- **Цитаты в сыром виде сохраняй в конце** (секция «Сырые выдержки») — на случай если пользователь захочет переформулировать.
- **Пиши на языке, на котором пользователь обращается в чате.**

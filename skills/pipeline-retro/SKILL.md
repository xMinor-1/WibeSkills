# pipeline-retro

Цель: **меньше токенов, выше качество, меньше дублей** в скиллах, `_shared/` и `CLAUDE.md`. Не оптимизирует код продукта — только процесс.

Контекст — `../_shared/project-config.md` + проектный `CLAUDE.md`.

## Шаг 0: план + approve

Всегда. Скилл правит общие инструкции — ошибка стоит дорого.

План в формате владельца продукта: что меняю (список файлов + суть); ожидаемый эффект («−1500 строк ≈ −30% контекста»); риски; что **не** трогаю. Жду «ок» / «поехали». Без approve — только чтение и отчёт.

## Когда НЕ запускать

- Эпик в работе (`task-build`/`task-test`/`task-ship` не закрыт) — дождись завершения.
- Свежий запуск pipeline-retro <2 недели назад без новых данных.

## Источники анализа

| Источник | Что ищем |
|---|---|
| `<библиотека>/*/SKILL.md` | размер, дубли, мёртвые секции, неверная модель в `recommended_model` |
| `_shared/*.md` | дубли между общими файлами |
| проектный `CLAUDE.md` | дубли со скиллами, устаревшие правила, противоречия |
| `_shared/project-config.md` | незаполненные поля, на которые опираются скиллы |
| `git log --since='8 weeks'` | какие скиллы реально использовались |
| `DOCS_ROOT/*/stories.md` (последний эпик/2) | где задачи зависали, какие шаги pipeline проскакивали |
| `pipeline-retro/CHANGELOG.md` | что уже меняли — не повторять |
| memory `feedback_*` | свежие feedback'и, ещё не отражённые в скиллах |

## Чек-лист аудита

1. **Размер скиллов.** `SKILL.md` >200 строк — кандидат на сокращение или разнос на под-файлы. Считай суммарный объём — это «налог» каждой сессии.
2. **Дубли.** Один блок в N скиллах → в `CLAUDE.md` / `_shared/`. Совпадение >30 строк подряд — обязательно консолидировать.
3. **Неиспользуемое / мёртвое.** Скиллы без вызовов за период; секции «что было раньше».
4. **Модель.** `recommended_model = opus`, но работа — детерминированный шаблон → Sonnet. И наоборот.
5. **Несогласованность с `CLAUDE.md`.** Старые workflow-номера, исчезнувшие слои.
6. **Pipeline gaps.** Шаг постоянно проскакивается → удалить или упростить. Ручной мост между шагами → автоматизировать.
7. **Свежий feedback.** Новые `memory/feedback_*` не отражены в скиллах.

## Формат отчёта

```
# pipeline-retro YYYY-MM-DD
## Цифры до
- Суммарно SKILL.md: X строк / ≈Y токенов
- Самые тяжёлые: skill A (N), skill B (M)
## Найдено (top-5 проблем по эффекту)
1. <проблема> — где, на сколько строк, как чинится
## Предлагаю править
- [ ] file:line — конкретное действие — экономия ≈N строк
## НЕ трогаю
- <список> — почему
## Цифры после (прогноз)
- Суммарно: X' (−Δ%)
```

После approve — вношу правки **по одной**, после каждой `wc -l` и сверка с прогнозом.

## Техника сокращения SKILL.md (по убыванию эффекта)

1. Вынести шаблоны в `templates/<name>.md` — грузятся по ссылке.
2. Убрать примеры, оставить 1 короткий.
3. Свернуть таблицы: 3 одинаковых по структуре колонки → буллеты.
4. Убрать риторику («важно понимать», «давай разберёмся») — императив.
5. Дедупнуть с `CLAUDE.md` / `_shared/` — если правило уже там, в скилле строка-ссылка.
6. Сжать списки до чек-листов.

Цель по умолчанию: **−30% строк** на ретро, без потери смысла.

## Применение правок

- Один коммит на одну тему.
- После каждого коммита — `wc -l` и обновить CHANGELOG.
- Не удалять скилл одной правкой — сначала пометить deprecated в `description`, на следующем ретро подтвердить и удалить.

## Журнал

Каждый запуск пишет запись в `pipeline-retro/CHANGELOG.md`: До/После (строки, %), Сделано, Отложено, Гипотеза на следующее ретро.

## Анти-паттерны

- Рефакторить скиллы «потому что красивее» без цифрового эффекта.
- Удалять `description` во frontmatter ради краткости — он нужен для активации.
- Сливать скиллы разных моделей в один.
- Менять формат `stories.md` / `_shared/backlog.md` — вне scope.
- Трогать продуктовый код или `VISION_DOC` / `PRD_DOC` — не наша зона.

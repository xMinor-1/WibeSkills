## Функциональные требования (FR)
Что система **делает**. Каждый FR ссылается на 1+ AC и должен быть автотестируем.

| #     | Требование                                       | AC   | Story | Автотест                         |
|-------|--------------------------------------------------|------|-------|----------------------------------|
| FR-1  | <Кто> <вводит/нажимает> X → <получает/видит> Y   | AC-1 | 1     | `e2e/<feature>/<test-name>.spec` |
| FR-2  | ...                                              | AC-2 | 1     | ...                              |

## Нефункциональные требования (NFR)
Качество и UX-инварианты. Каждый NFR **обязан** иметь автопроверку — либо переформулируй, либо переведи в edge case с manual.

| Категория     | Требование                                       | Метод автопроверки                          |
|---------------|--------------------------------------------------|---------------------------------------------|
| Performance   | <операция> отвечает <N> мс (p95)                 | e2e + измерение времени                     |
| Performance   | First Contentful Paint <1.5s на 3G mobile        | Lighthouse CI                               |
| UX-инвариант  | <элемент> sticky (всегда виден при скролле)      | e2e + DOM-проверка `position: sticky`       |
| UX-инвариант  | <элемент> не перекрывается клавиатурой           | e2e mobile + `visualViewport`               |
| Accessibility | Контраст текста ≥ WCAG AA на критичных экранах   | `axe-core` в e2e fixture                    |
| Mobile        | Layout не ломается на 320px width                | e2e viewport=320                            |
| Security      | Input не уязвим к XSS / инъекциям                | автоматический payload в e2e                |

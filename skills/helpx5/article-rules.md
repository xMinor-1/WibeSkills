# Правила статьи help-центра — выжимка для агента

Полные версии: `Help-центр/md-format.md` (разметка), `Руководство-по-статьям.md`,
`rukovodstvo-po-kontentu.md` (стиль), `content-ops.md` §2 (категории).
Здесь — то, без чего статья не примется.

## Каркас файла

```markdown
---
title: Как принять рейс в работу
audience: перевозчик          # перевозчик | водитель | грузовладелец | все
roles: логист, диспетчер      # необязательно, бейдж «Кому доступно»
category: reisy-i-zayavki     # слаг существующей категории
order: 120                    # шаг 10, новые статьи с 110 и дальше
slug: kak-prinyat-reys-v-rabotu
---

> **Коротко:** одним-двумя предложениями — ответ на вопрос заголовка.

## Веб-ЛК

1. Откройте раздел **«Рейсы»**.
   ![Список рейсов, статус «Не взят в работу»](reisy-spisok.png)
2. Отметьте нужные рейсы и нажмите **«Взять в работу»**.

## Приложение

1. Откройте вкладку **«Рейсы»** внизу экрана.

> ⚠️ **Важно:** пока водитель не верифицирован, назначить его нельзя.

> 💡 **Совет:** можно взять сразу несколько рейсов — отметьте галочками.

## Частые вопросы

### Что будет, если не подтвердить рейс вовремя?
Ответ в одно-два предложения.
```

## Жёсткие требования

1. Первый блок — всегда `> **Коротко:**`. Без него статья не проходит.
2. Заголовки платформ — ровно `## Веб-ЛК` и `## Приложение` (ключи табов). Если статья
   только про веб — секцию «Приложение» не выдумывать.
   **Веб-ЛК всегда идёт первым**: веб-кабинет — основная поверхность, приложение вторая.
   **В блоках только различия.** Всё, что одинаково на обеих поверхностях — условия,
   ограничения, что получится в итоге, куда смотреть дальше — выносится **до** блоков
   (если это нужно знать заранее) или **после** них (если это следствие). Одна и та же
   фраза в двух блоках — ошибка: читатель видит только свою вкладку и всё равно прочтёт
   вынесенное. То же правило действует внутри любого другого блока статьи, где расходятся
   поверхности (например, «Если нужно заменить ТС»): сначала общий абзац, затем различия.
   Исключение: статья целиком про одну поверхность — тогда блок один, выносить нечего.
3. Один шаг — одно действие. Повелительное наклонение, обращение на «вы» со строчной.
4. Скриншот — строкой сразу после текста шага, без пустой строки, подпись в alt
   осмысленная (её видит читатель). Модификаторы: `|w=480`, `|l`, `|i`.
5. FAQ — только `###`-вопросы внутри `## Частые вопросы`.
6. Без HTML, без таблиц шире 3 колонок, без вложенности списков глубже двух уровней.
7. Слаг — транслитерация заголовка, латиница со строчной через дефис.

## Стиль

| Не так (язык вики/системы) | Так (язык help) |
|---|---|
| «Необходимо будет выбрать причину отказа в открывшемся модальном окне» | «Выберите причину отказа» |
| «Осуществляется переход в раздел» | «Откройте раздел» |
| «Система предоставляет возможность» | «Вы можете» |
| «В случае возникновения ошибки» | «Если появилась ошибка» |
| «Данный функционал» | «Эта возможность» / просто назвать |

- Заголовок статьи — задача пользователя словами пользователя: «Как принять рейс в работу»,
  а не «Функционал принятия рейсов».
- Термины интерфейса — точно как на экране, в кавычках-ёлочках и жирным: **«Взять в работу»**.
- Числа и сроки — только из материала. Нет в материале — не пишем.
- Никаких «в современном мире», «мощный инструмент», «бесшовно». Никаких декоративных эмодзи;
  допустимы только `⚠️` и `💡` как ключи плашек.

## Объединять или дробить

- **Объединять**, если страницы вики по 3–5 строк описывают шаги одной пользовательской
  задачи («Просмотр рейсов» + «Принятие рейсов» + «Завершение рейсов» → одна статья
  «Как вести рейс от получения до закрытия», если шагов немного).
- **Дробить**, если в одной странице вики смешаны задачи разных ролей или разных этапов
  (регистрация + справочники) — это разные статьи.
- Ориентир: статья закрывает один вопрос целиком, читается за 2–3 минуты, шагов ≤ 12.

## Медиа

- Картинки из выгрузок вики уже лежат рядом с текстом — брать их, а не рисовать заново.
- Кадры из видео — только если они читаемы (текст на экране виден) и показывают шаг,
  который словами объяснить сложно.
- Класть в `knowledge-base/media/<слаг>/`, имя файла = имя в ссылке статьи.
- В `content-map.json` фиксировать источник каждого медиа: имя материала + локатор
  (страница вики, `стр. 7`, `12:34` для видео).

## Карта связей

Каждая написанная/изменённая статья добавляет запись в `knowledge-base/content-map.json`:

```json
{
  "articles": {
    "kak-prinyat-reys-v-rabotu": {
      "sources": [
        {"material": "2026-08-11-lkc-trk", "locator": "5.2. Принятие рейсов в работу (592095175)"},
        {"material": "demo torgi v2.mp4", "locator": "01:12–02:40"}
      ],
      "media": ["reisy-spisok.png"],
      "change_reason": "добавлен шаг подтверждения рейса из свежей выгрузки"
    }
  }
}
```

`change_reason` заполняется только при правке существующей статьи — он попадает в
`CHANGES.md` пакета и объясняет получателю, зачем трогали статью.

## Переключатели (вкладки)

Подряд идущие секции `## Таб: <Название>` фронт собирает в группу вкладок. Легаси-имена
`## Веб-ЛК` и `## Приложение` работают так же, без префикса.

Вкладки — для равноправных путей: способы взять груз (фикс / аукцион / встречное), роли,
тарифные схемы. Внутри вкладки порядок обычный: сначала веб-кабинет (`### Веб-кабинет`),
затем приложение (`### Приложение`), и только различия.

Не вкладки: последовательные шаги одного процесса, перечисление возможностей раздела,
частые вопросы.

## Картинки

- Подпись описывает, что на кадре: **что за экран и что на нём видно**. Имя файла в подписи —
  брак (`![image-2026-7-24_18-50-13.png]`).
- Ширина задаётся маркером `|w=` — `![подпись|w=320](url)`. Считать от высоты кадра, чтобы
  картинка не занимала весь экран читателя: `w = 520 × ширина / высота`, для снимков телефона
  не больше 320.
- Кадр показывает то, о чём говорит шаг. Если в шаге «нажмите кнопку X», на кадре должна быть
  видна кнопка X, а не соседняя область.

# Epic Preview

Создаёшь **статичный HTML-прототип эпика** — один файл с Tailwind CDN, без бэка, без фреймворка. Цель: за 10–15 минут получить кликабельный макет, который пользователь открывает в браузере и говорит «да/нет/переделай».

Контекст — `../_shared/project-config.md` + проектный `CLAUDE.md`. Approve — `../_shared/approve-protocol.md`. Хендофф — `../_shared/handoff-protocol.md`. Хранение артефактов — `../_shared/artifact-storage.md`.

## Старт

Approve **не нужен** (создание HTML в `DOCS_ROOT/`). Иду делать сразу.

## Шаг 1: Чтение PRD

Прочитай `DOCS_ROOT/<epic-slug>/PRD.md`. Если PRD нет — стоп: «Сначала запусти `epic-prd`».

Из PRD вытащи:
- Job + сегмент → tone дизайна
- Acceptance criteria → определяют экраны
- Edge cases → один экран — edge (пустое состояние, ошибка)

## Шаг 2: Один HTML-файл = эталон UI

Структура: один `<!doctype html>` файл, Tailwind через CDN, кастомный шрифт, навигация между секциями через `data-screen` + чистый JS без зависимостей. Моки данных — хардкодом.

**Preview — это эталон UI, не вдохновение.** Реализация в `task-build` обязана повторять разметку pixel-perfect (visual regression проверит).

**Жёсткое правило: те же CSS-переменные / классы, что в реальном коде.**
- CSS-переменные темы — копировать из существующей дизайн-системы проекта (`CODE_ROOT`) или ссылаться на ту же палитру.
- Атомарные классы — те же, что в существующих компонентах. Не выдумывай свои.
- Шрифт — из существующей дизайн-системы проекта, не «придумай красивый».
- Предлагаешь новый класс / переменную — добавь его в продакт-тему **в той же задаче** (или вынеси в follow-up Task).

Это нужно, чтобы переход preview → реализация = подключение данных + обёртка, а не пересоздание UI.

## Шаг 3: Что показывать

3–5 экранов: точка входа в фичу, ключевое действие (AC #1), успех, один edge case. Не делай весь продукт — только эпик.

## Шаг 4: Дизайн (mobile-first)

- Уникальный шрифт (не дефолтный системный).
- Один смелый акцентный цвет + сдержанный фон.
- Mobile-first (320–414px), но `md:` для desktop.
- **Без AI-slop:** никаких фиолетовых градиентов на белом, никаких generic-карточек.
- Тон — из `BRAND_VOICE` в project-config (если модуль D заполнен), иначе из tone PRD.
- Не уверен в синтаксисе свежих Tailwind-классов — Context7 MCP за актуальной докой (если подключён). Не для базового набора.

## Шаг 5: Сохранение

Сохрани прототип в `DOCS_ROOT/<epic-slug>/preview/index.html`. Обнови строку `🎨 preview/index.html` в блоке «📚 Артефакты эпика» в `PRD.md` на `✅ готов`.

## Шаг 6: Реальный гейт ⏸

Открой файл локально (`open DOCS_ROOT/<epic-slug>/preview/index.html`).

> «Preview готов: `DOCS_ROOT/<epic-slug>/preview/index.html`. Открой в браузере и скажи: ✅ ок / переделай / правки.»

**Жди ответа.** Это `⏸ wait` гейт — решает человек.

После «переделай» — переделываю **полностью**, не по чуть-чуть. Эталон ещё не зафиксирован. Гейт повторяется.

После «✅ ок» preview становится эталоном:
1. Скопируй финальный HTML в `CODE_ROOT/e2e/preview-fixtures/<epic-slug>/` (одним файлом или по экранам) — это baseline для visual regression в `task-test`.
2. Готовь хендофф.

## Шаг 7: Хендофф

Применяй `../_shared/handoff-protocol.md` (только после ✅ на гейте):
> Готово: preview эпика `<slug>` — `DOCS_ROOT/<slug>/preview/index.html`, эталон скопирован в e2e-фикстуры
> Следующий шаг: epic-tech-spec
> Промпт: `Запусти epic-tech-spec для эпика "<slug>". PRD и preview — в DOCS_ROOT/<slug>/.`

## Принципы

- Один файл, без build-шагов, без установки зависимостей.
- Без сторонних JS-библиотек кроме Tailwind CDN.
- Не пиши код фреймворка — это прототип.
- Не подключай реальную БД — данные хардкодом.

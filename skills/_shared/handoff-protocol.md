# Handoff-протокол — передача между чатами

**Каждое исполнение скилла = отдельный чат.** Скилл делает свою работу, кладёт артефакт на диск и **готовит хендофф** — не продолжает pipeline в том же чате.

## Почему так

Контекст чата растёт с каждым шагом. Если гнать весь эпик в одном чате — модель «забывает» начало, ответы дорожают, растёт риск ошибок. Граница чата = сброс контекста. Всё, что нужно следующему шагу, лежит на диске в `DOCS_ROOT/<epic-slug>/`, а не в переписке.

## Что умеет и не умеет харнесс

Скилл **не может** сам очистить чат или сам отправить сообщение в новый чат — в Claude Code нет такого инструмента. Поэтому «автоматически» на практике = скилл готовит **готовый к вставке промпт**, а пользователь одним движением открывает новый чат и вставляет его. Это самый автоматический вариант, который возможен.

## Формат хендофф-блока

Скилл pipeline заканчивает работу этим блоком — и больше ничем (без trailing summary):

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
🚪 ХЕНДОФФ — открой новый чат

Готово: <что сделано, где лежит артефакт — 1 строка>
Следующий шаг: <название-скилла>

Вставь в новый чат:
┌──────────────────────────────────
│ <самодостаточный промпт: скилл + slug эпика/стори + путь к артефактам>
└──────────────────────────────────
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

Промпт внутри блока **самодостаточен** — называет скилл, slug эпика/Story и пути к артефактам, чтобы новый чат стартовал без переписки. Пример:
`Запусти epic-tech-spec для эпика "otp-auth". PRD и preview лежат в docs/otp-auth/.`

## Карта pipeline

Каждая стрелка = граница чата.

| Чат (скилл) | Следующий чат | Гейт перед хендоффом |
|---|---|---|
| `market-research` *(опц.)* | `epic-prd` | — (вердикт «идея жизнеспособна») |
| `epic-prd` | `epic-preview` | — |
| `epic-preview` | `epic-tech-spec` | ⏸ визуальный осмотр preview в браузере |
| `epic-tech-spec` | `epic-arch-review` | — |
| `epic-arch-review` | `agile-coach decompose` | NO-GO → возврат в `epic-tech-spec` / `epic-prd` |
| `agile-coach decompose` | `task-build` (первая Task) | — (декомпозиция в `stories.md`) |
| `task-build` | `task-cross-review` | — |
| `task-cross-review` | `task-test` | CHANGES/BLOCK → возврат в `task-build` (лимит 2 раунда) |
| `task-test` (Task не последняя в Story) | `task-docs` | — |
| `task-docs` | `task-build` (следующая Task) | — |
| `task-test` (последняя Task Story) | `task-ship` | ⏸ Story manual gate на prod-build |
| `task-ship` | `task-build` (следующая Story) | ⏸ бизнес-summary + ✅ перед деплоем |
| `task-ship` (последняя Story эпика) | — | эпик закрыт; через 1–2 недели `analytics-insights` |

**Вне pipeline (standalone, по запросу):** `epic-legal-review`, `tracker-sync`, `analytics-insights`, `pipeline-retro`, все `marketing-*`. Они не готовят хендофф в следующий скилл — заканчивают обычным коротким результатом.

## Реальные гейты ⏸

Гейт = действие живого человека. Скилл доводит до гейта, проговаривает что проверить, **ждёт ответ пользователя** — и только потом готовит хендофф-блок.

- `epic-preview` — пользователь открывает preview в браузере, говорит ✅ / переделай.
- `task-test` (последняя Task Story) — Story manual gate: пользователь открывает на prod-build, проверяет AC Story.
- `task-ship` — бизнес-summary что меняется + ✅ перед деплоем.

## Возвратные петли

Возврат назад — это **тоже новый чат** с хендофф-блоком, направленным назад.

| Петля | Лимит | После лимита |
|---|---|---|
| `cross-review` → `build` | 2 раунда per Task | эскалация пользователю: «не сходимся, нужно решение» |
| `task-build` `LOCAL_CHECK` авто-fix | 3 попытки | стоп, отчёт |
| `task-test` unit авто-fix | 3 попытки | стоп, отчёт |
| `task-test` e2e авто-fix | 1 повтор | стоп, отчёт |
| `arch-review` NO-GO → `tech-spec`/`prd` | — | возврат с конкретным списком |

Счётчик раунда пиши в `stories.md` рядом с Task (`cross-review раунд 2/2`) — виден в стендапе.

## Запреты

- Не продолжай pipeline в том же чате после своего хендофф-блока.
- Не задавай «открыть новый чат?» — просто готовь блок.
- Не тащи в новый чат пересказ переписки — только артефакты на диске.
- Не пытайся пройти ⏸-гейт сам — там решает человек.

## Откат

Хендофф-модель что-то ломает — пользователь говорит «стоп», возвращаешься к ручному переходу для этого шага. Корректировка карты — на ближайшем `pipeline-retro`.

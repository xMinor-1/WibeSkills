# Режим проекта — app vs work

Поле **MODE** в `<project>/.claude/project-config.md` (раздел ЯДРО) задаёт, какой контур
скиллов уместен для проекта. Это главный переключатель между двумя видами работы.

MODE — первая из двух осей поведения. Вторая, ортогональная — **TRACK** (сколько discovery
и для кого PRD): [tracks.md](tracks.md). Единая карта «какие скиллы когда» — таблица pipeline
в [handoff-protocol.md](handoff-protocol.md); здесь только специфика оси MODE (guard'ы).

| | **`app`** (вайб-код) | **`work`** (операционка) |
|---|---|---|
| Кто доводит до прода | **я**, от и до | **живой программист** по итогу |
| Цель | рабочее приложение в проде | **пакет для передачи**: проработка → PRD → прототип → спека |
| Финал инженерной части | merge + тесты + деплой (`task-ship`) | **handoff-пакет** разработчику (`dev-handoff`) |
| Git / ветки / worktree | обязательны | по ситуации, не по умолчанию |
| Пример проекта | leftbook.ai | x5transport |

## Как определить режим

1. Читай `MODE` из `<project>/.claude/project-config.md`.
2. Поля `MODE` нет или конфига нет → **дефолт `app`** (обратная совместимость со старым pipeline).
3. Явное противоречие (MODE=app, но нет `CODE_ROOT`/git; или MODE=work, а просят полный деплой) → не угадывай, спроси одной строкой.

## Что в каком контуре

**Общие для обоих режимов** (нейтральны к MODE, ничего не меняют):
`market-research`, `craft-value-proposition`, `ask-nmt`, `epic-prd`, `agile-coach`,
все `marketing-*`, `video-distill`, `analytics-insights`, `tracker-sync`, `pipeline-retro`, `epic-legal-review`.

**Адаптируются под MODE** (меняют поведение/адресата):
- `epic-preview` — в `work` не требует PRD и не копирует baseline в e2e-фикстуры; быстрый макет для согласования.
- `epic-tech-spec` — в `work` пишется как спека **для внешнего программиста** (стек, схема, эндпоинты, инфра), а не внутренний план.

**Только `app`** (в `work` не разворачиваются — см. guard ниже):
`epic-arch-review`, `task-build`, `task-test`, `task-cross-review`, `task-ship`.

**Только `work`**:
`dev-handoff` — собирает пакет для живого разработчика (PRD + прототип + tech-spec + инфра-контекст).

## Guard для app-only скиллов

Если скилл помечен «Только `app`», в начале:
> Прочитай `MODE`. Если `work` — **не разворачивай полный pipeline**. Объясни одной строкой,
> почему здесь финальный код пишет живой программист, и предложи `dev-handoff` (или
> `epic-tech-spec` в work-режиме как спеку). Жди решения, прежде чем что-то делать.

В `app` (или если MODE не задан) — работай как обычно, этот блок пропусти.

## Принцип work-режима: «лёгкий, но с подстраховкой»

В `work` делай быстро и без бюрократии — но три подстраховки обязательны:
1. **Перед боевым деплоем** (выкатка на `cms.wibecodex5t.ru`, контент в Strapi, прод-артефакты)
   — покажи результат и дождись ✅.
2. **Перед удалением/перезаписью** боевых данных или чужих файлов — спроси.
3. **Smoke-проверка** — если есть что прогнать (скрипт, сборка прототипа), прогони один раз
   перед сдачей. Полный pipeline тестов не нужен.

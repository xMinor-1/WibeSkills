# Жизненный цикл чата

**Правило: один чат = один дирижёр эпика; один шаг pipeline = свой чистый контекст.** Диалоговые и оркестрирующие
шаги (`kickoff`, `market-research`, `craft-value-proposition`, `epic-prd`, `delivery-run`, `task-ship`, гейты) идут
в самом чате, автономные — сабагентами, которых дирижёр запускает сам. Переход — по [handoff-protocol.md](handoff-protocol.md),
delivery — по [delivery-workflow.md](delivery-workflow.md).

Граница шага = граница артефактов на диске. Всё, что нужно следующему шагу, лежит в `DOCS_ROOT/` (и в git).
Переписка в сабагента не переезжает: решения владельца, которых ещё нет в артефактах, дирижёр передаёт дайджестом
в промпте. Что важно надолго — фиксируй в файл.

## Почему не «весь эпик в одном контексте»

Раньше зона = чат (весь эпик или вся Story в одном чате) — контекст переполнялся к концу зоны. Потом стало
«один скилл = новый чат» — контекст чистый, но пользователь вручную переносил промпты. Сейчас чистый контекст
даёт сабагент, а переход делает дирижёр: в главный чат возвращаются только короткие отчёты.

## Что переезжает между шагами

**Без потерь (на диске / в git):**
- `DOCS_ROOT/<epic-slug>/` — PRD, preview, tech-spec, arch-review, market-research
- `DOCS_ROOT/<epic-slug>/stories.md` — файловый бэклог эпика (Stories + Tasks + статусы), ведёт `agile-coach`
- `DOCS_ROOT/<feature-slug>/` — user/support/analytics документация
- feature-ветки и worktree'и (см. [worktree-protocol.md](worktree-protocol.md))
- `CLAUDE.md`, `_shared/`, memory

**С потерями:** переписка, нюансы устного обсуждения. Нужно сохранить — в файл/`stories.md` или в дайджест промпта следующего шага.

## Когда всё же новый чат

- Главный чат разросся (длинное интервью + много шагов) или пауза 30+ минут (prompt cache выгорел) — дирижёр
  фиксирует состояние в артефактах и даёт хендофф-блок ручного режима.
- Работа переезжает в другой тред, на другую машину или в фоновую сессию (`go`).
- Параллельный эпик — свой чат-дирижёр.

## Короткие чаты (без перехода к следующему шагу)

Standalone-скиллы — каждый свой короткий чат, заканчивается обычным результатом:
- `nmt-chat` — продуктовый советник по канону NMT, диалог и есть результат
- `triz-resolve` — решатель по ТРИЗ, диалог и есть результат
- `video-distill` — конспект транскрипта по запросу
- `watch` — просмотр видео по ссылке (транскрипт + кадры)
- `epic-legal-review` — по запросу
- `tracker-sync` — по запросу
- `todo` — быстрый захват задач в GitHub Issues, одиночно или пачкой
- `analytics-insights` — через 1–2 недели после релиза
- `pipeline-retro` — мета-ретро
- любой `marketing-*`
- `agile-coach` в режимах стендап / груминг / прогресс / приоритеты

## Параллельная работа

Можно вести несколько чатов-дирижёров одновременно: параллельные эпики, параллельные Story одного эпика.
Параллельные Task внутри delivery — сабагенты Workflow внутри одного рана `delivery-run`. Изоляция — через
worktree'и и git-ветки.

**Нельзя:** два чата или два сабагента редактируют один файл в одной ветке, не зная друг о друге. Граф зависимостей
в `stories.md` — источник правды о том, что параллелится.

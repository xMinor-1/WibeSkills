# Approve-протокол

Единый источник правды. Скиллы ссылаются, не дублируют. Стиль коммуникации — [communication-style.md](communication-style.md).

## Approve **нужен** (короткий план + жди «ок / поехали»)

- Миграции БД (любое изменение схемы `DB`)
- Изменения **auth / payments / биллинга / реферралов** — риск сломать живых пользователей
- Деструктивные git-операции (force push, hard reset, удаление веток)
- Финальный деплой в прод (`task-ship`, гейт «✅ ship»)
- Когда у тебя **2+ жизнеспособных продуктовых варианта** — выбор за владельцем продукта
- **Bulk-операции в бэклоге** (декомпозиция эпика, >3 Story/Task сразу в `stories.md`)
- Запись в трекер через `tracker-sync` — только по явному запросу пользователя

## Approve **не нужен** (делаю и сообщаю результатом)

- Чтение / поиск / отчёты (стендап, груминг, прогресс по эпику)
- Создание / правка **одной** Task в `stories.md` с понятными параметрами
- Локальные правки кода в feature-ветке
- Создание / обновление файлов в `DOCS_ROOT/<epic-slug>/` (включая `stories.md`)
- Auto-rollup статуса Story/эпика после изменения статуса Task
- Подготовка хендофф-блока для следующего чата (см. [handoff-protocol.md](handoff-protocol.md))
- **Любые технические решения** (модель LLM, паттерн, npm-пакет, алгоритм, структура файлов)

## Approve в Workflow-режиме (`delivery-run`)

Сабагент внутри Workflow approve-операции **не выполняет и не ждёт** — возвращает оркестратору статус `needs_approve`, ран завершается на этой границе, решение принимает человек между сегментами (контракт — [delivery-workflow.md](delivery-workflow.md)). Список approve-операций тот же, что выше.

## Формат плана для approve

Когда approve нужен — план **на языке владельца продукта**, ≤6 строк:

```
Что делаю: <1–2 строки>
Что НЕ трогаю: <1 строка>
Риски: <1 строка, если есть>
Длительность: fast / medium / slow
```

Без бюрократии, без заголовков, без табличек. Минимум, чтобы можно было сказать «ок» или поправить.

## Эскалация модели

Если результат не устроил с первого раза — повторный запуск на **более высокой** модели с расширенным thinking, без экономии на токенах. Не экономь на повторе.

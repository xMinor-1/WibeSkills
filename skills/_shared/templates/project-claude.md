# Шаблон: CLAUDE.md проекта

> Шаблон из библиотеки скиллов. Копируй структуру, не файл.
> Назначение: за 30 секунд понять, что за проект, в каком он состоянии и где материалы.
> **Конвенция: файл ≤100 строк** (за превышение агент получает требование от хука-сторожа харнеса).
> Здесь — только то, что нужно в каждой сессии. Правило про конкретный модуль — в
> `.claude/rules/<тема>.md` с `paths:` во frontmatter: Claude Code подгружает его, только когда
> агент читает или правит совпадающие файлы. Длинные справочники — отдельными файлами по ссылке. Для инструментального проекта с готовым
> README достаточно тонкой обёртки: суть + ссылка на README + режимы.

```markdown
# <Проект> — суть и правила

<2-4 строки: что это, для кого, текущий статус (идея / MVP / прод / поддержка).>

## Режимы

- **MODE** — `app | work` (см. `.claude/project-config.md`; справка — `_shared/mode.md`)
- **TRACK_DEFAULT** — `fast | prd | indie | enterprise` (дефолт трека для kickoff; справка — `_shared/tracks.md`)

## Где что лежит

| Что | Где |
|---|---|
| <код / артефакты / доки / бэклог> | <путь> |

## Правила проекта

<Только сквозная специфика проекта: стек-указатель, дизайн-система, деплой-нюанс, юр-режим.
Общие протоколы НЕ дублировать — ссылаться на `_shared/*`.>

Память проекта — `~/.claude/memory/<группа>/INDEX.md`, прочитай перед работой.

## Правила по модулям — `.claude/rules/`

Новое правило про модуль — в `.claude/rules/<тема>.md`, не в этот файл:

    ---
    paths:
      - "src/<модуль>/**"
    ---
    # <тема>
    - <правило>

| Файл правил | О чём | paths |
|---|---|---|
| `<тема>.md` | <о чём> | `<globs>` |

## Стиль

Коммуникация и артефакты — по `_shared/communication-style.md` (human-артефакты = zero-slop).
```

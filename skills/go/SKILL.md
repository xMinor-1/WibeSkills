# go — перенос работы в фоновую сессию, переживающую обрыв связи

## Что это делает

Запускает **отдельный Claude Code внутри tmux** на сервере:

- tmux не привязан к SSH/VS Code → обрыв связи, закрытый ноут и упавший extension host его не убивают;
- фоновая сессия форкает контекст текущего чата (`--resume <id> --fork-session`) — помнит всё, о чём говорили;
- работает headless (`--print`): отрабатывает задачу до конца и выходит, никаких вопросов и подтверждений;
- текущий чат остаётся живым и свободным.

Движок — `go.sh` в папке скилла. Раны лежат в `~/.claude/go-runs/<name>/`
(`prompt.txt`, `meta.env`, `cmd.sh`, `raw.log`; `REPORT.md` пишет сама сессия — требование
скрипт дописывает в каждый промпт автоматически). Повтор имени завершённого рана не удаляет
его папку, а убирает в `~/.claude/go-runs/.old/`.

## Как выполнять

### 1. Собери ТЗ для фоновой сессии

Фоновая сессия **не может задать вопрос** — некому ответить. Промпт должен быть
самодостаточным ТЗ, даже при наследовании контекста:

- что именно сделать — конкретно, по пунктам;
- где — пути, проект, прод/локально;
- критерий готовности — «страница открывается и отдаёт 200», «тесты зелёные»;
- поведение на развилке: выбрать разумный вариант, продолжить, зафиксировать выбор в отчёте —
  **не останавливаться и не ждать**;
- запреты: не пушить в прод / не трогать чужие файлы / удалять только в `archive/_trash-YYYY-MM-DD/`;
- финал: базовое требование «запиши итог в REPORT.md» скрипт добавит сам; если отчёт нужен
  в особом разрезе (что проверить владельцу, какие метрики снять) — пропиши это в ТЗ явно.

Если пользователь написал просто `/go` без задачи — сформулируй ТЗ сам из того, над чем работаем
сейчас, и покажи его одной строкой в ответе.

### 2. Запусти

```bash
"<папка скилла>/go.sh" run "<ТЗ одним текстом>" --name <короткое-имя> --dir "<корень проекта>"
```

- контекст текущего чата наследуется автоматически (из env `CLAUDE_CODE_SESSION_ID`);
  `--fresh` — чистая сессия, если контекст не нужен (дешевле);
- права по умолчанию `bypassPermissions` — иначе фон встанет на первом же вопросе;
  `--safe` (acceptEdits) — если задача трогает чужой прод;
- `--dir` указывай явно: корень проекта, а не cwd bash-инструмента;
- `--effort` наследуется из текущей сессии (env `CLAUDE_EFFORT`); `--model` НЕ наследуется —
  без флага фон стартует на модели из глобальных настроек. Если чат работает на другой модели
  и это важно — укажи `--model` явно.

### 3. Доложи пользователю коротко

- имя рана и что ему поручено — одна строка;
- напомни: **вернуть результат в чат — `/goon`** (или `/goon <имя>` при нескольких ранах);
- если задача длинная — предложи посмотреть позже, а не ждать в чате.

## Управление ранами

```bash
go.sh list                 # какие раны есть и что с ними
go.sh status <name>        # работает / простаивает / остановлена
go.sh log <name> [N]       # последние N сообщений (чистый текст из jsonl сессии)
go.sh tail <name>          # живой хвост вывода терминала
go.sh more <name> "<что ещё сделать>"   # продолжить сессию новой задачей, контекст сохраняется
go.sh back <name>          # id рана + готовые команды для ручного возврата
go.sh stop <name>          # остановить
go.sh attach <name>        # подключиться к окну tmux (только из живого терминала)
```

`attach` из чата не вызывай — он блокирует терминал. Состояние проверяй через `log`/`status`.
Возврат результата в чат — скилл `/goon` (SKILL.md рядом: `../goon/`).

## Ограничения (говорить честно)

- Фон работает под тем же аккаунтом → ест тот же 5-часовой лимит, что и этот чат.
- Режим headless: диалога с фоновой сессией нет. Догрузить задачу — `go.sh more`
  (продолжает ту же сессию с её контекстом), а не через attach.
- `--tui` (интерактивное окно, к которому можно подключиться и переписываться) работает:
  CLI залогинен 02.08.2026. Но `bypassPermissions` в интерактивном окне требует разового
  подтверждения диалога — пока владелец его не принял, скрипт сам понижает права до `acceptEdits`
  и пишет об этом. Не нажимай это подтверждение за владельца.
- MCP-коннекторы с интерактивной OAuth (claude.ai, Notion, Drive) в фоне могут быть недоступны —
  задачи под них в фон не отдавать.
- `bypassPermissions` = никто не спросит подтверждения: разрушительные операции запрещай в ТЗ явно.
- Фоновая сессия — форк: её работа не возвращается в этот чат сама, результат забирается
  скиллом `/goon`.

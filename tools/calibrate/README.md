# Калибровка исполнителей — методика

Сравнение моделей на **своих** задачах вместо чужих бенчмарков. SWE-bench меряет другое:
одиночный баг-фикс в чужом репозитории, без вашей архитектуры слоёв, preview-эталона
и событий аналитики. Предсказательной силы для конкретного pipeline у него нет.

Материал для замера уже есть: закрытая Task — это готовый эталон. Известен правильный дифф,
известны тесты, известна зона правок. Откатываем реализацию, отдаём пакет исполнителю,
сравниваем результат.

## Что меряем

| Метрика | Как снимается | Что означает |
|---|---|---|
| Зелёное с первого прогона | `VERIFY_CMD` сразу после исполнителя | пригодность к этому классу задач |
| Раундов cross-review | прогон `task-cross-review`, вручную | сколько правок докидывать после «готово» |
| Выходы за границы | `out_of_scope` в вердикте | держит ли исполнитель рамку пакета |
| Стоимость и время | отчёт провайдера + `wall_clock_s` | во что обходится экономия |

Меньше 8–10 Task на исполнителя — выборка мала, выводы не делаются. Разброс между
типами Task (domain / use-case / infra / ui / migration) больше, чем между соседними
моделями, поэтому набор обязан покрывать все типы.

## Набор задач (LiftBook, client-cabinet)

Из 67 закрытых Task эпика берём по 2 на слой. Пример стартового набора:

| Task | Слой | Чем интересна |
|---|---|---|
| `S4-1-domain-tokens-and-hash` | domain | чистые функции, много правил, нет инфраструктуры |
| `S4-2-usecase-create-invite` | use-case | порты, транзакция, порядок проверок |
| `S7-4-ui-balance-hero-and-history` | ui | preview-эталон, состояния, маскировка |
| `S3-2-middleware-cab-routes` | infra | матрица маршрутов, Edge-ограничения |
| `S6-2-ledger-infra-drizzle` | infra/db | ORM, запросы, транзакции |
| `S1-5-migration-0013` | migration | approve-класс, для замера не берём |

Task с `[approve]`-операциями (миграции, схема) в замер **не входят**: исполнитель обязан
на них останавливаться, и это правильное поведение, а не провал.

## Порядок прогона

```bash
export REPO="$HOME/Work/3. projects/LiftBook"

./calibrate.sh prepare S4-1-domain-tokens-and-hash   # песочница «до», тесты обязаны стать красными
./calibrate.sh run     S4-1-domain-tokens-and-hash sonnet
./calibrate.sh run     S4-1-domain-tokens-and-hash haiku
./calibrate.sh score                                  # свод
./calibrate.sh clean                                  # убрать песочницы
```

`prepare` создаёт отдельный git worktree вне рабочей копии, откатывает файлы реализации
из `allowed-paths` (тесты и пакет остаются) и проверяет, что тесты действительно красные.
Зелёные тесты на откаченном коде означают, что задача для замера не годится — метрика
измерит не то.

Каждый `run` — реальные деньги. Скрипт ничего не запускает сам и не ходит за ключами.

## Чем можно прогнать сегодня (проверено 08.08.2026)

| Исполнитель | Статус в этом окружении |
|---|---|
| Opus / Sonnet / Haiku | **доступны** — через тот же CLI, что и основная работа, ключей докупать не нужно |
| DeepSeek, Qwen | **недоступны**: ни CLI, ни API-ключей в окружении нет |
| LiteLLM, aider, ollama, claude-code-router | не установлены |

Проверка: `command -v litellm aider ollama qwen ccr` — пусто; переменных `*_API_KEY`
для сторонних провайдеров нет; глобально из npm стоят только `corepack` и `npm`.

Отсюда практический порядок: **сначала замерить Sonnet и Haiku против Opus** — это
бесплатно в смысле новых доступов и отвечает на главный вопрос («можно ли отдать fill вниз
внутри Anthropic»). Внешние провайдеры подключать после того, как цифры по младшим моделям
Anthropic покажут, что разделение architect/implementer вообще работает.

Что нужно для внешнего прогона: ключ провайдера + один CLI-исполнитель (aider или
совместимый), затем раскомментировать строку в `EXECUTORS` внутри `calibrate.sh`.
Ни того, ни другого этот заход не приобретал.

## Как читать результат

- Доля зелёных низкая, выходов за границы нет → модель слабее, но рамку держит: пробуйте
  подробнее контракт интерфейсов и мельче Task.
- Доля зелёных низкая **и** выходы за границы есть → проблема в пакете, а не в модели:
  зона правок описана неточно либо AC размыты.
- Доля зелёных высокая, но раундов ревью много → тесты покрывают не то, что важно людям;
  чинится не сменой модели, а красными тестами на реальные AC.
